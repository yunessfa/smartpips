# نتیجه تست این تحویل

## اجرا شده
- Django: 154 تست؛ 153 موفق و 1 تست اجرای کتابخانه اختیاری در محیط عادی skip شده است.
- همان مجموعه پژوهشی با کتابخانه backtesting 0.6.5 در مسیر وابستگی ایزوله: 7 تست موفق، بدون skip.
- Node: هر 15 تست موفق؛ شامل رفرش، خروجی ژورنال و کنترل پاسخ دیررس.
- Vite production build موفق؛ هشدار غیرمسدودکننده حجم chunk باقی است.
- مرورگر Chromium محلی، API کاملاً ساختگی و بدون تماس خارجی: دسکتاپ1440 و موبایل390، انتخاب موتور و payload، هشدار پژوهشی، دلایل انتظار در اسکالپ/مودال؛ بدون خطای JS و overflow افقی موبایل.
- ارتفاع ظرف بالای چارت همچنان 80%. فایل PositionChart، Panel عمومی، accounts، alerts، auth و API client نسبت به بسته قبلی بدون تغییر.
- ارتقای SQLite با state مهاجرت trades.0007 به 0008 و حفظ مقادیر قدیمی و اجرای مجدد: موفق. این تست نصب صفر یا PostgreSQL نیست.
- مقایسه state واقعی فایل‌های migration با مدل‌ها: بدون تغییر معوق ({}).
- bash -n اسکریپت انتشار و compileall پایتون موفق.

## حدود اعتبار
- هیچ نصب روی سرور، سفارش واقعی یا فراخوانی خصوصی صرافی انجام نشده است.
- Docker و PostgreSQL در محیط تست در دسترس نبودند؛ build کانتینری/مهاجرت سرور باید هنگام استقرار کنترل شود.
- تست‌های عادی Django با config.test_settings و بدون اجرای تاریخچه قدیمی migration اجرا می‌شوند؛ آزمون migration مستقل بالا فقط مسیر ارتقای نصب موجود را شبیه‌سازی می‌کند. تاریخچه قدیمی برای نصب صفر تأیید نشده است.
- holdout زمانی با پارامترهای ثابت اضافه شده؛ از اکسل معاملات به تنهایی بهینه‌سازی معتبر یا اثبات افزایش سود به دست نمی‌آید. اجرای ارزیابی واقعی نیازمند OHLCV مناسب است.
- ریسک دمو آزمایشی و محافظه‌کارانه است، نه پارامتر بهینه‌شده آماری. بر پایه موجودی واردشده، زیان روز UTC و هزینه تخمینی است؛ گپ و زیان شناور می‌تواند از بودجه عبور کند.
- پایش دمو هر10ثانیه قیمت مشاهده‌شده را می‌بیند و لمس بین نمونه‌ها را تضمین نمی‌کند.
- تطبیق واقعی فقط پیش‌نمایش خواندنی است؛ هزینه و سود خالص تأییدنشده خالی می‌مانند.
- native و backtesting.py فرض اجرای یکسان ندارند؛ پژوهشی نتیجه فعال‌سازی نمی‌سازد.

## بازاجرای آزمون‌ها
```bash
cd backend
DJANGO_SETTINGS_MODULE=config.test_settings python manage.py test --noinput
# محیط جداگانه با requirements-research.txt نصب‌شده:
DJANGO_SETTINGS_MODULE=config.test_settings python manage.py test apps.strategy.test_research_revision --noinput
cd ../frontend
npm ci
npm test
npm run build
```
پیش از اجرای تست‌ها روی سرور تولید، از محیط و دیتابیس جداگانه استفاده کنید.
